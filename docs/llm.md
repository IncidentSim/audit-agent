# Вызов DeepSeek с хоста проверки

Команды выполняются из корня `audit-agent`. [Вернуться в README](../README.md).

Клиент работает на Python 3.10+ со стандартной библиотекой, на Windows/Linux/macOS.
Ключ и клиент держите на хосте проверки; пользовательской microVM ключ не нужен.
`install.py` устанавливает только сборщик: вызов LLM выполняется отдельно из
исходного/распакованного каталога. Автоматический запуск из бота/валидатора пока
не подключён. Внешняя система вызывает клиент после `stop` и самой валидации.

1. Создайте API key в [DeepSeek Platform](https://platform.deepseek.com/api_keys).
   Для API нужен доступный баланс в этом аккаунте. Подробности:
   [первый запрос](https://api-docs.deepseek.com/),
   [модели и списание средств](https://api-docs.deepseek.com/quick_start/pricing/).
2. Скопируйте `config/llm.example.json` в `config/llm.local.json`. Пути внутри настроек
   разрешаются относительно файла настроек, а пути аргументов CLI — относительно
   текущего каталога. В этом рабочем каталоге локальная копия уже подготовлена.
3. Создайте `.secrets/deepseek-api-key` в корне репозитория и вставьте туда
   только ключ, одной строкой. На Linux каталог должен быть 0700, файл 0600.
   Альтернатива — переменная окружения `DEEPSEEK_API_KEY` процесса клиента;
   она имеет приоритет над файлом. Вставлять ключ в JSON не нужно.

`config/llm.local.json`, `.secrets/`, `.env` и локальные отчёты `analysis/` исключены из
Git и переносимого архива. В репозиторий входит только пример без ключа.
Хосту проверки нужен исходящий HTTPS к `api.deepseek.com:443` и системные CA.
Используется стандартная настройка HTTP(S) proxy окружения Python.

Подготовьте `task.md` (проблема, цель, критерии успешного решения) и `validation.json`
или текстовый отчёт валидатора. Заберите с microVM `llm.json`, путь к которому
вернул `stop`. Полные audit logs для обычного запроса не нужны.

```bash
# Из audit-agent: проверить входные данные и размер запроса без ключа и сети.
python3 src/analyze.py --input /path/to/llm.json --task /path/to/task.md \
  --validation /path/to/validation.json --dry-run

# Настоящий платный запрос. Каталог output должен быть новым.
python3 src/analyze.py --input /path/to/llm.json --task /path/to/task.md \
  --validation /path/to/validation.json --output analysis/attempt-001
```

На Windows используйте `python` вместо `python3`. Если валидация ещё не готова,
можно опустить `--validation`: модель получит явное указание об отсутствии результата.
Ответ: `analysis.md` и `analysis.json` с профилем, фактической моделью, SHA256
пакета/запроса и `usage`, возвращённым API. Ключ и промежуточные рассуждения
в отчёт не записываются. Для каждого запуска нужен новый каталог результатов;
это защищает от случайного повторного платного запроса.

По умолчанию выбран `deepseek-flash`, адрес `https://api.deepseek.com`,
thinking выключен, ответ ограничен 2000 токенами, таймаут — 120 секунд.
Все эти настройки находятся в профиле `deepseek`. API описан в
[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/).
`parameters` передаются в тело запроса: например, там можно изменить `max_tokens`
или режим thinking. Лимиты `max_request_bytes`/`max_response_bytes` относятся к
байтам, а не токенам. При превышении входного лимита запрос не отправляется;
автоматического усечения команд нет. При `finish_reason != stop` отчёт не
публикуется: увеличьте лимит ответа/измените модель и запустите явно повторно.
Автоматических повторных запросов при сетевых ошибках нет.

Для другого провайдера добавьте профиль в `profiles`: `adapter`, `base_url`,
`model`, `api_key_env`/`api_key_file`, `timeout_seconds`, `parameters`.
Смените `active_profile` или используйте `--profile имя --config /path/to/settings.json`.
Поддерживается совместимый Chat Completions API, адрес может включать `/v1`.
Параметры DeepSeek (например `thinking`) в профиль другого API переносить не нужно.
Для несовместимого протокола потребуется новый адаптер в клиенте; сейчас такой
профиль отклоняется явно. Инструкция модели настраивается через `prompt_file`.
